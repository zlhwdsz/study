# 可寻址

## 特例：复合字面量（隐式新建变量）

“可寻址“ 与 ”允许使用 &“ 并不完全等价，全因一个特例：复合字面量本身并不可寻址，本身不是普通可寻址表达式，但 `&T{...}` 是取地址表达式的特例，会创建一个新的唯一变量并返回其地址。

```go
_ = &struct{ X int }{X: 1}
_ = &[3]int{1, 2, 3}
_ = &[]int{1, 2, 3}
```

`p := &T{X: 1}` 规范上可以理解成：
```go
tmp := T{X: 1}
p := &tmp
```

所以`p` 指向的是一个真实存在的变量位置。于是 `_ = &p.X` 可以，因为它会被自动解释成 `_ = &(*p).X`，而`*p` 是指针解引用，指针解引用结果是可寻址的；`(*p).X` 是可寻址对象的字段，所以也可寻址。

但注意这几个层次不同：
```go
_ = &T{X: 1}        // 可以：& 对复合字面量的特例
_ = &T{X: 1}.X      // 不可以：T{...}.X 不是可寻址字段
_ = &(&T{X: 1}).X   // 可以：先得到 *T，再通过指针访问字段
_ = &&T{X: 1}       // 不可以：&T{...} 这个指针值本身是临时结果
```

根因是： `&T{...}` 把复合字面量落成了一个隐式变量；后续通过这个指针解引用访问对象时，访问到的是变量位置，而不是临时表达式结果。

## 可寻址完整列表

可寻址：不是看值底层有没有内存，而是看这个表达式是否代表一个**稳定的变量位置**。
- 变量：&x
- 指针解引用：&(*p)，包括 p.X 隐式转换成的 (\*p).X。
- 可寻址结构体字段：&s.Field。结构体字面量不可寻址，所以其字段亦不可寻址。
- 可寻址数组索引：&arr[0], &(*pa)[0]。数组字面量不可寻址，所以其索引亦不可寻址。
- 切片索引，哪怕是字面量：[✓] &[]int{1,2,3}[0]  (切片的底层数组实际不会变，所谓扩容是生成了一个新的底层数组和新的切片)。上文已经阐述，其他复合字面量的索引是不可寻址的，比如 [X] &[3]int{1, 2, 3}[0]。对比起来有些反直觉，但 Go 规范就是这么规定的。

如上，要拿到除切片外的复合字面量的字段/元素的地址，可以先拿到复合字面量自身的地址，然后再拿字段/元素的地址：
```go
_ = &(&[3]int{1, 2, 3})[1]
_ = &(&struct{ X int }{X: 1}).X
```

## 不可寻址

其他的都不可寻址且不可使用 &：
- 常量和字面量方面：
  - 常量
  - 非复合类型的字面量，包括函数字面量，即匿名函数
  - 算术操作的结果
  - 非切片的复合字面量的索引表达式，比如数组字面量、map 字面量的的索引
  - 任何复合字面量的切片表达式
- 变量方面：
  - string 变量的索引表达式和切片表达式不可寻址。
  - map 变量的索引表达式不可寻址。
  - 函数类型的变量可寻址，但由 func 定义的函数名、方法名不算变量，不可寻址。
- 临时结果：函数/方法调用表达式不可寻址（除非返回指针，然后 p.X 造成指针解引用），包括类型转换表达式、类型断言表达式、通道接收表达式。

## 可寻址与赋值的关系

赋值语句左边的每个操作数必须是：
1. 可寻址的表达式；
2. map 索引表达式；
3. 空标识符 _，仅限普通 = 赋值。

++/-- 左边仅接受前两种情况。
