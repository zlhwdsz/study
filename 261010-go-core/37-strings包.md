# 多字符串高效拼接

首先排除 fmt.Sprintf：即使是固定数量字符串拼接 `fmt.Sprintf("%s%s%s%s", ss[0], ss[1], ss[2], ss[3])`，也有格式解析和`string → any` 装箱分配的性能损耗。

元素数量固定且很少：`s1+s2+s3`，被编译器合并优化，通常是内存分配仅一次、每个字符串被也都被复制一次。

已有字符串切片：
- `for; s1 += s2`: 每次两两拼接都创建新的 string：分配新的内存，复制新串+越来越长的临时结果串，非常低效。
- `bytes.Buffer` / `strings.Builder`: 
  - 底层操作字节切片，即使未提前分配所有空间，由于切片不像 string 一样不可变，而是可容量>长度，所以不会像 += 那样频繁地分配空间、复制数据。
  - 更何况可用 Grow 提前分配所有空间，这样分配空间、每个字符串的复制都仅有一次。
  - 最后返回时，Buffer.String() 本质是 []byte 到 string 的类型转换，会重新分配空间，而 **Builder.String() 不会再重新分配空间而是原地返回，更优。**
  - 用 Builder 实现、性能稍低但简单的方式：`strings.Join(elems, sep)`

动态：使用 `strings.Builder`

Builder 在已被真正使用后（非零值）就禁按值复制（Builder 中的 addr 字段就是用来干这个事的），防止两个 Builder 共享缓冲区，破坏已生成字符串的不可变性。传指针是可以的。
