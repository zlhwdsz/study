# ps: process status

## ps 字段

UID/USER：有效用户 ID，也就是 EUID / EUSER (effective，偏“当前按谁的权限运行”，启动后可更改) 而不是 RUID / RUSER (real，偏“是谁启动/登录来的”)。二者一般相同，可同时查看：
```bash
ps -eo pid,ruid,ruser,euid,euser,comm
```

TTY: 进程关联的终端。如果某个进程的`TTY` 是`?` ，通常表示它没有绑定到具体终端，比如后台服务进程。
- /dev/tty*(teletypewriter，电传打字机，泛化成“终端设备”的概念): 纯字符终端
- pty(pseudo teletypewriter，伪终端): 伪终端整体机制，组伪终端通常分成两端：PTY master  <->  PTS slave
  - `pty master` 这一端由终端模拟器、SSH 服务端、tmux 等程序控制，负责接收你的键盘输入、显示程序输出。
  - `pts` (pseudo terminal slave，伪终端从设备，/dev/pts/*，`ps`命令可能输出的 TTY 字段) 这一端给 shell、vim、top 这类程序使用，看起来就像真实终端。通常对应你打开的一个个“虚拟终端会话”，比如：
    - SSH 登录后的终端
    - 图形界面里打开的 Terminal 标签页
    - VS Code / Trae 里的集成终端
    - `tmux` /`screen` 里的终端窗口
- 另：`tty` 命令显示当前终端对应的设备文件。

TIME 字段不太具有参考价值。

PPID: 父进程 ID。

## ps 选项

ps 默认只列出：当前用户+当前终端的进程。

Unix/System V 风格选项(可组合)：
- -a: 所有用户 + 所有终端(排除"?")，排除 session leaders。
- -e(every) / -A(all)：所有用户 + 所有终端 + 无终端后台进程。
- -f(full-format)：完整格式， including command lines
- -L(LWP)：Show threads, possibly with LWP(Light Weight Process，即线程) and NLWP(Number of LWP) columns.
-  -o, o, --format <format>：user-defined format

BSD (Berkeley Software Distribution，基于 Unix 做的一套系统发行版)风格选项（可组合）：
- a: 所有用户 + 所有终端(排除"?")。
- e: 当前用户 + 所有终端(排除"?")，同时显示进程的环境变量。
- x: 显示没有控制终端 TTY 的进程。
- u: user-oriented format，按用户友好的格式显示。

ps 也支持 GNU long options, which are preceded by two dashes，具值选项可同时通过空格和"="连接。

## 1 号进程

Linux 用户空间的第一个进程是 PID 1 进程。现代发行版通常是 systemd；较早系统（比如 CentOS）通常是 init。

## header

up: 系统运行时间

2 users: 登录用户

load average: 1/5/15 分钟系统的平均负载（繁忙程度），1 表示满负载运行。

tasks: 进程数。

%Cpu(s): 按 CPU 时间分类统计出来的百分比（按 `1`：所有逻辑 CPU 切换单独/汇总平均显示）
- us: user，普通用户态程序占用的 CPU 时间。
- sy: system，内核态占用的 CPU 时间，例如系统调用、内核线程。
- ni: nice，调整过 nice 优先级的用户进程占用的 CPU 时间。
- id: idle，CPU 空闲时间。
- wa: iowait，等待 I/O 完成的时间，常用于观察磁盘或网络 I/O 压力。
- hi: hardware irq(Interrupt Request)，处理硬件中断占用的 CPU 时间。
- si: software irq，处理软中断占用的 CPU 时间，例如网络包处理。
- st: steal, 虚拟机想用 CPU 但被宿主机拿走的时间。
```text
us 高      应用程序计算忙
sy 高      内核/系统调用/内核线程忙
wa 高      I/O 等待明显，可能磁盘或网络慢
id 高      CPU 比较空闲
st 高      虚拟机环境下 CPU 被宿主机争用
hi/si 高   中断处理多，尤其 si 高时常见于网络包处理压力
```

## table 字段

每一行是一个进程。按 `f` 可以选择显示字段；按 `P` 按 CPU 排序，按 `M` 按内存排序，按 `c` 切换显示命令名/完整命令行。

- PID: 进程 ID。
- USER: 进程的有效用户，一般可理解为当前按哪个用户权限运行。
- PR(priority): 内核调度优先级，受 nice 值影响。实时任务可能显示为 `rt`(real time)。
- NI(nice): nice 值，影响普通进程调度优先级。`-20` 优先级高，`19` 优先级低，默认通常是 `0`。
- VIRT(virtual memory): 进程可见的虚拟地址空间总量，不等于实际占用的物理内存。
- RES(resident memory): 常驻物理内存大小，更接近进程实际占用的内存。
- SHR(shared memory): `RES` 中可与其他进程共享的部分，比如共享库、映射文件。
- S(state): 进程状态。
  - R(running): 正在运行或可运行。
  - S(sleeping): 可中断睡眠，常见等待状态。
  - D(uninterruptible sleep): 不可中断睡眠，常见于等待 I/O。
  - Z(zombie): 僵尸进程。
  - T(stopped): 停止/暂停。
- %CPU: 刷新间隔内的 CPU 使用率。多线程进程可能超过 `100%`。
- %MEM: 内存占比，通常可理解为 `RES` 占总物理内存的比例。
- TIME+: 进程从启动到现在累计消耗的 CPU 时间，不是进程运行了多久。
- COMMAND: 命令名；按 `c` 可切换为完整命令行。

# nice: 调 nice 值影响进程优先级

nice 值，影响普通进程调度优先级(PR)。`-20` 优先级高，`19` 优先级低，默认通常是 `0`。

启动时设置 nice 值：`nice -n/--adjustment 10 COMMAND`

对运行中的进程调优先级：`renice -n 10 COMMAND PID`

# jobs: 当前终端后台进程

&：将进程放到后台进程组中，后台运行。

`fg 当前终端后台进程编号(从1开始)`：将后台进程调至前台运行(哪怕之前处于挂起状态)

ctrl+z: 将前台进程调至后台**挂起**(stopped, T)。

`bg`：让被挂起的后台进程继续运行。


# kill

选项：
    -s 信号	<信号> 是信号名称，s 可忽略
    -n 信号	<信号> 是信号编号，n 可忽略
    -l/-L	列出所有信号名称；如果 "-l" 后有参数，则假定它们是信号编号，
        并列出对应的信号名称

- 1) SIGHUP(hangup): 终端挂断信号。早期表示用户断开终端连接，默认终止相关进程，可捕获/忽略/自定义处理。很多守护进程也约定收到 SIGHUP 后重新加载配置；`nohup` 的作用就是让进程忽略 SIGHUP。
- 2) SIGINT(interrupt, ctrl+c)：终端中断信号，默认终止前台进程，可捕获/忽略/自定义处理。
- 3) SIGQUIT(`ctrl+\`): 终端退出信号，默认终止并产生 core dump，可捕获/忽略/自定义处理。常用于调试。
- 9) SIGKILL: 内核强制终止进程，程序没有收尾机会。
- 15) SIGTERM(kill 默认发送): 请求进程正常终止，适合让服务/后台进程正常退出，可捕获/忽略/自定义处理。

# nohup：临时长任务

nohup 命令：
- 让输出重定向到 nohup.out(可通过 > 符改动)。
- 让进程收到 SIGHUP 信号（终端退出时发送）时，不是终止进程，而是与终端解绑(ps 终端字段变为 "?")，同时改认 PID 1 为父进程。

但终端退出时，其他清理动作，比如清理前台进程组，nohup 并不能处理，所以一般 nohup 会配合 & 一起使用。

# 守护进程：正式服务

systemd 启动的守护进程与 nohup 启动的后台进程：
- 相同之处：
  - 最终父进程都是 1，绑定的终端都是 "?"。
- 不同之处：
  - nohup 启动进程需要终端，但 systemd 启动进程不需要终端。
  - /prot/PID/cwd：nohup 方式为执行命令时的目录，systemd 方式为 /。
  - /proc/PID/fd/{1,2}: nohup 方式为 nohup.out 或另外指定，systemd 方式为 socket（再由系统日志服务 journald 处理）。
