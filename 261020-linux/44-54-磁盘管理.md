# 磁盘分区查看：fdisk -l， parted -l

fdisk: fixed disk，“固定磁盘/硬盘”，不是`format disk` 。`fdisk` 主要负责 创建、删除、查看、修改分区表。

ls -l /dev/sd*: 对于磁盘设备文件来说，在文件大小的字段处，显示的是 "主设备号, 从设备号"。
- 主设备号：用什么驱动程序。
- 从设备号：确定访问地址。

```bash
8, 0 /dev/sda
8, 1 /dev/sda1 # 分区，最多分15个区
8, 2 /dev/sda2
8, 3 /dev/sda3
8, 16 /dev/sdb
8, 32 /dev/sdc
```

# 磁盘分区使用量：df, disk free

如果是 ext4 文件系统，会从超级块中快速拿到信息，而不是每个文件逐一统计。

# 文件的磁盘占用：du, disk usage

与 ls -l 相比，du 总是能精确地返回实际磁盘占用。

du 以数据块(比如 4k)为单位，所以 du 看到的大小可能大于 ls -l 看到的大小。

而由于空洞的存在，同一个文件，du 看到的大小又可能会小于 ls -l 看到的大小！（例见下节）

# 按块读写：dd, data duplicator

和普通`cp` 不同，`dd` 更偏底层，按块读写，可以直接操作设备文件：

```bash
# if: input file, of: output file, bs: block size
dd if=/dev/zero of=afile bs=4M count=10 # afile: ls -l 和 du 都是 40M。
dd if=/dev/zero of=bfile bs=4M count=10 seek=20 # ls -l 显示 120M（只查看 inode）, du 显示 40M (会查看 data block)。
```

# 文件系统(ext4->xfs)

CentOS: ext4 -> xfs.

## inode

ext4 结构：
- 超级块
- 超级块副本（存储在很多 data blocks 中）
- i 节点(inode, index node): 记录文件的元数据：权限、属主、大小、时间戳、链接数、数据块位置等；对于目录文件来说，还会记录目录下的文件名->inode number 映射（所以一个文件 inode 不会记录自身的名称。当目录内文件太多时，还会记录到目录的 data block 里）。
- 数据块(data block)：多个数据块会形成链接结构。

vi 工作原理：
- 开始编辑文件后，会另存一个 .swp 文件
- w 保存时，原文件名 -> 新 inode -> 新 data block

rm 工作原理：仅删除文件名 -> inode number 映射，inode 和 datablock 本身都不会立即删除。

ln 硬链接工作原理：仅添加文件名 -> 原 inode number 映射，不会增加额外的空间。不能跨分区/文件系统创建硬链接。

软链接/符号链接：可以跨分区，新建文件（但不含底层内容，只含映射信息），inode number 不同。l 类型文件权限是无意义的 777，对其所做的权限修改都会(递归地)传递到 target 文件去生效。

# 磁盘分区设置: fdisk, mkfs, parted（>2T）, mount

fdisk: 在磁盘(比如/dev/sdc)上创建 primary（最多4个）/extended（内部可再建逻辑分区）分区(比如 /dev/sdc1)
- m: menu
- n: add a new partition

parted：对容量 > 2T 的磁盘进行分区。

mkfs: 对分区格式化、制作文件系统，创建 inode, blocks 等。

mount: 临时挂载。固化：/etc/fstab (file systems table)
